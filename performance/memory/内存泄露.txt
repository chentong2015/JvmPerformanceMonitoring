TODO. 发生OOM的三个JVM运行时内存区域
1. Thread Stack Overflow 线程栈溢出 -> java.lang.StackOverflowError
   产生条件: 每次调用方法时都会在栈中存储相应的数据，无限递归调用时会造成StackOverflow
   解决方法:
   - Fix Bug 修改源码问题
   - ReservedStackAccess 使用注解预留栈空间预防溢出

2. MetaSpace 元空间溢出 -> java.lang.OutOfMemoryError: Metaspace
   产生条件: 元空间中主要存储类的信息，当程序运行时加载过多的类时会造成OOM
   泄露场景: 当通过反射加载类型时，可能会造成过多的代理类(例如ProxyEntity)被加载到元空间中

3. Heap 堆空间OOM溢出 -> java.lang.OutOfMemoryError Java heap space
   产生条件: 创建的对象通常存储在堆空间，当持续创建过多或无法被GC回收的对象时，会造成堆空间被填满
   泄露场景:
   - 堆内存过小(或设置过小)，无法满足程序的运行需求
   - 长期产生无法GC的对象，从GC Roots起点可达
   - 数据资源泄露(对象没有即时清理)，例如DB连接未关闭
   解决方法:
   - Set Maximum heap size 增加堆空间大小
   - Dump heap memory      分析内存堆中数据
   - Java Monitoring Tool  监测造成OOM的过程
